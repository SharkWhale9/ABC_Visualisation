What can — and can't — ABC tell you about an epidemic?

Approximate Bayesian Computation estimates parameters without ever writing down a likelihood: simulate, compare to the data, keep what's close. Using one stochastic SIR outbreak, this dashboard shows two things — ABC recovers the reproduction number R0 reliably even when it can't separate β from γ, and a Markov chain sampler reaches the same posterior far more cheaply than blind rejection sampling once both are given the same simulation budget.

Likelihood-free inference, briefly

Why ABC, and how does it work?

Ordinary Bayesian inference combines a prior with a likelihood: p(θ | data) ∝ p(data | θ) · p(θ). For a stochastic epidemic, that likelihood involves summing over every possible sequence of daily infections and recoveries consistent with the data — intractable in general. ABC sidesteps the likelihood entirely: if you can simulate from the model, you don't need to be able to evaluate it.

1. Draw

Sample candidate parameters (β, γ) from the prior — no data used yet, exactly as in standard Bayesian inference.

2. Simulate

Run the stochastic SIR model forward from those parameters to generate a full synthetic epidemic.

3. Compare & accept

Reduce the simulation to a summary statistic, measure its distance from the observed summary, and keep the draw only if that distance is small enough.

Surviving draws are treated as approximate samples from the posterior. The approximation has two knobs, both explored below: which summary statistic defines "close," and how the surviving draws are generated — independently from the prior (rejection) or via a Markov chain (ABC-MCMC).

Method 01 · independent prior proposals

ABC rejection sampling — and what it can identify

Draw parameters from the prior, simulate one epidemic, and keep the closest proposals to the observed summary. Acceptance here is percentile-based: instead of a hand-tuned absolute tolerance, you choose what fraction of the simulation budget survives, so the rich and poor summaries can be compared on equal footing.

Why percentile, not raw ε

A fixed absolute ε accepts very different counts under different summaries, confounding "the summary is less informative" with "more points were let through." Percentile acceptance removes that confound.

Lossy summaries

Final size alone cannot distinguish fast, sharp outbreaks from slower, longer ones with similar totals — hence the wider, more degenerate ridge.

Method 02 · same budget, dependent local proposals

Dependent states

The next proposal is centered on the current state, so retained draws are autocorrelated and must not be interpreted as independent simulations.

Acceptance rule

With uniform priors and a symmetric random walk, an in-bounds proposal is accepted exactly when its simulated distance is below ε. Out-of-bounds proposals cost no SIR simulation — they're free, and don't draw down the shared budget.

Same budget, different yield

Rejection spends all of B on independent prior draws. MCMC spends B on initialization plus a local random walk that, once inside the compatible region, keeps landing nearby — so a much larger share of its budget produces usable posterior states.

Appendix — simulator validation and full source code

Model check

Does the stochastic simulator behave sensibly?

For each parameter regime, 500 seeded stochastic trajectories are compared with the deterministic SIR ODE. This is a software-correctness check, not part of the ABC story above — it exists so you can trust the engine behind it.

Supercritical outbreaks

Expected small differences

The daily binomial process is not algebraically identical to the continuous-time ODE, so discretization and nonlinear averaging produce modest offsets.
